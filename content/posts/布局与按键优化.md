## 2. 项目目录地图

```text
my-blog/
├── hugo.toml                         # Hugo 站点配置
├── archetypes/
│   └── default.md                    # 新文章模板
├── content/                          # 网站的 Markdown 内容
│   ├── archives.md                   # 归档页入口
│   └── posts/                        # 博客文章
├── layouts/                          # 本地模板覆盖，优先于主题模板
│   ├── index.html                    # 首页布局
│   └── partials/
│       └── extend_head.html          # 向 <head> 插入自定义内容
├── assets/                           # Hugo Pipes 可处理的资源
│   └── css/custom.css                # 目前存在，但没有被当前模板引用
├── static/                           # 原样复制到网站根目录的静态文件
│   ├── 321.jpg                       # 头像图片
│   └── css/custom.css                # 当前生效的自定义样式
├── themes/PaperMod/                  # Git submodule：PaperMod 主题
├── data/                             # 可选的数据文件目录
├── i18n/                             # 可选的界面翻译文件目录
├── .github/workflows/
│   └── hugo-deploy.yml               # GitHub Pages 自动部署工作流
├── public/                           # Hugo 生成的网站文件，不要手工修改
└── resources/                        # Hugo Pipes 缓存（生成时可能出现）
```

### 哪些目录是“源文件”，哪些是“生成结果”？

- `content/`、`layouts/`、`static/`、`assets/`、`hugo.toml` 是维护网站时主要编辑的源文件。
- `public/` 是 Hugo 构建出来的 HTML、CSS、图片等发布文件。直接改这里，下一次构建会覆盖修改；也复制一遍你的文章在这里
- `themes/PaperMod/` 是主题子模块。主题升级或切换时，直接改主题内部文件的修改可能丢失。
- `assets/css/custom.css` 和 `static/css/custom.css` 目前有相似样式，但实际加载的是 `static/css/custom.css`。要改首页 profile 样式，请改 `static/css/custom.css`，不要把改动只写进 `assets/css/custom.css`。

## 3. Hugo 如何把文件变成网页

可以把 Hugo 的工作理解成一条流水线：

1. 从 `hugo.toml` 读取站点名称、主题、菜单和参数。
2. 读取 `content/` 中的 Markdown 和 front matter。
3. 按页面类型选择本地 `layouts/` 或 `themes/PaperMod/layouts/` 中的模板。
4. 将 `static/` 内文件复制到输出目录；将模板和内容渲染成 HTML。
5. 把最终网站写入 `public/`。

## 4. 常见修改

### 

推荐用命令生成模板：

```powershell
hugo new posts/my-first-post.md
```

然后编辑 `content/posts/my-first-post.md`：

```markdown
---
title: "我的第一篇文章"
date: 2026-10-18T18:00:00+08:00
draft: false
categories: ["学习技术"]
tags: ["Hugo", "写作"]
summary: "用一句话说明这篇文章讲什么。"
---

## 从一个问题开始

正文使用 Markdown 编写。先写结论，再按小标题拆分步骤。
```

- `draft: true` 表示草稿；本地可用 `hugo server -D` 预览草稿，正式构建时通常不会发布。
- `categories` 用于分类，`tags` 用于标签。当前首页的分类区块通过 `site.Taxonomies.categories` 读取分类。
- 每篇文章最好只设一个主要分类；标签用于补充主题词。
- Markdown 标题从 `##` 开始作为正文一级小节，避免正文标题层级跳跃。

也可以复制现有文章再改标题、日期和内容。模板默认值由 `archetypes/default.md` 控制。

### 修改首页的分类文章显示

打开 `layouts/index.html`。这个模板现在负责调用 profile partial，并遍历分类文章：

```go-html-template
{{ range $term, $pages := site.Taxonomies.categories }}
  <h3>{{ $term }}</h3>
  {{ range $pages }}
    <a href="{{ .RelPermalink }}">{{ .Title }}</a>
  {{ end }}
{{ end }}
```

常见变量：

- `site.Title`：站点标题。
- `.Title`：当前页面或文章标题。
- `.RelPermalink`：自动包含站点子路径的站内链接，优先用于文章链接。
- `.Summary`：文章摘要。可以在 front matter 中写 `summary`，也可以用正文开头生成摘要。
- `site.Taxonomies.categories`：所有分类及其文章集合。

修改模板后，注意保留 Hugo 的 `{{ ... }}` 双大括号语法。模板不是普通 HTML，变量和循环必须由 Hugo 渲染。

## 5. 初级页面优化玩法

###  提升文章可读性

- 开头先交代问题、结论或读者能学到什么。
- 每个段落只讲一个重点；步骤使用有序列表，选项使用无序列表。
- 命令和代码用代码围栏，并标注语言：

  ````markdown
  ```powershell
  hugo server -D
  ```
  ````

- 图片应有意义且文件大小适中；将图片放到 `static/images/`，正文中使用：

  ```markdown
  ![页面效果截图](/blog/images/page-preview.png)
  ```

  若希望本地预览和生产站点都不受路径影响，可在 Hugo 模板中使用 `relURL`；Markdown 图片也可用站点根路径写法，但应确认该路径带有 `/blog/`。

## 6. 本地预览、构建与发布

在项目根目录打开 PowerShell：

```powershell
# 启动本地预览；草稿文章也会显示
hugo server 
```

浏览器访问：<http://localhost:1313/blog/>。保存文件后 Hugo 通常会自动刷新。CSS 没更新时，先强制刷新浏览器；如果本地服务器未重新加载，再停止并重新运行命令

```powershell
git add .
git commit -m "Update blog content and layout"
git push
```

只把本次真正修改的文件加入提交。不要把临时构建目录、个人缓存或无关文件一起提交。
