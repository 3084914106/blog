## 2. 项目目录地图

```text
my-blog/
├── hugo.toml                         # Hugo 站点配置
├── archetypes/
│   └── default.md                    # 新文章模板
├── content/                          # 网站的 Markdown 内容
│   ├── archives.md                   # 归档页入口
│   └── posts/                        # 博客文章
├── layouts/                          # 本地模板覆盖，优先于主题模板
│   ├── index.html                    # 首页布局
│   └── partials/
│       └── extend_head.html          # 向 <head> 插入自定义内容
├── assets/                           # Hugo Pipes 可处理的资源
│   └── css/custom.css                # 目前存在，但没有被当前模板引用
├── static/                           # 原样复制到网站根目录的静态文件
│   ├── 321.jpg                       # 头像图片
│   └── css/custom.css                # 当前生效的自定义样式
├── themes/PaperMod/                  # Git submodule：PaperMod 主题
├── data/                             # 可选的数据文件目录
├── i18n/                             # 可选的界面翻译文件目录
├── .github/workflows/
│   └── hugo-deploy.yml               # GitHub Pages 自动部署工作流
├── public/                           # Hugo 生成的网站文件，不要手工修改
└── resources/                        # Hugo Pipes 缓存（生成时可能出现）
```

### 哪些目录是“源文件”，哪些是“生成结果”？

- `content/`、`layouts/`、`static/`、`assets/`、`hugo.toml` 是维护网站时主要编辑的源文件。
- `public/` 是 Hugo 构建出来的 HTML、CSS、图片等发布文件。直接改这里，下一次构建会覆盖修改；应回到对应源文件修改。
- `themes/PaperMod/` 是主题子模块。主题升级或切换时，直接改主题内部文件的修改可能丢失。
- `assets/css/custom.css` 和 `static/css/custom.css` 目前有相似样式，但实际加载的是 `static/css/custom.css`。要改首页 profile 样式，请改 `static/css/custom.css`，不要把改动只写进 `assets/css/custom.css`。

## 3. Hugo 如何把文件变成网页

可以把 Hugo 的工作理解成一条流水线：

1. 从 `hugo.toml` 读取站点名称、主题、菜单和参数。
2. 读取 `content/` 中的 Markdown 和 front matter。
3. 按页面类型选择本地 `layouts/` 或 `themes/PaperMod/layouts/` 中的模板。
4. 将 `static/` 内文件复制到输出目录；将模板和内容渲染成 HTML。
5. 把最终网站写入 `public/`。

Hugo 会优先使用项目自己的布局覆盖主题布局。例如，`layouts/index.html` 用来覆盖主题首页模板。主题内部的 `layouts/_partials/` 是主题自己的 partial 目录；项目里使用 `layouts/partials/` 提供 `extend_head.html` 扩展点。

## 4. 常见修改：一步一步定位

### 修改站点名称或首页介绍

打开 `hugo.toml`：

```toml
title = "鑫垅笔记"

[params.profileMode]
  enabled = true
  subtitle = "写给未来自己的学习笔记"
  imageUrl = "321.jpg"
```

`imageUrl = "321.jpg"` 对应 `static/321.jpg`。更换头像时，替换这张图片或修改配置中的文件名，并将图片放进 `static/`。

### 增加或修改导航按钮

菜单项在 `hugo.toml` 的 `[[menu.main]]` 配置。首页 profile 按钮在 `params.profileMode.buttons` 配置：

```toml
  [params.profileMode]
    buttons = [
      { name = "文章", url = "posts/" },
      { name = "归档", url = "archives/" }
    ]
```

站点发布在 `/blog/` 子路径下，站内链接尽量使用相对站点根目录的路径（例如 `posts/`），或者在模板里用 Hugo 的 `relURL` / `.RelPermalink`。不要随手把路径写成域名根目录下的 `/posts/`，否则部署后可能跳出 `/blog/`。

### 新建文章

推荐用命令生成模板：

```powershell
hugo new posts/my-first-post.md
```

然后编辑 `content/posts/my-first-post.md`：

```markdown
---
title: "我的第一篇文章"
date: 2026-10-18T18:00:00+08:00
draft: false
categories: ["学习技术"]
tags: ["Hugo", "写作"]
summary: "用一句话说明这篇文章讲什么。"
---

## 从一个问题开始

正文使用 Markdown 编写。先写结论，再按小标题拆分步骤。
```

- `draft: true` 表示草稿；本地可用 `hugo server -D` 预览草稿，正式构建时通常不会发布。
- `categories` 用于分类，`tags` 用于标签。当前首页的分类区块通过 `site.Taxonomies.categories` 读取分类。
- 每篇文章最好只设一个主要分类；标签用于补充主题词。
- Markdown 标题从 `##` 开始作为正文一级小节，避免正文标题层级跳跃。

也可以复制现有文章再改标题、日期和内容。模板默认值由 `archetypes/default.md` 控制。

### 修改首页的分类文章显示

打开 `layouts/index.html`。这个模板现在负责调用 profile partial，并遍历分类文章：

```go-html-template
{{ range $term, $pages := site.Taxonomies.categories }}
  <h3>{{ $term }}</h3>
  {{ range $pages }}
    <a href="{{ .RelPermalink }}">{{ .Title }}</a>
  {{ end }}
{{ end }}
```

常见变量：

- `site.Title`：站点标题。
- `.Title`：当前页面或文章标题。
- `.RelPermalink`：自动包含站点子路径的站内链接，优先用于文章链接。
- `.Summary`：文章摘要。可以在 front matter 中写 `summary`，也可以用正文开头生成摘要。
- `site.Taxonomies.categories`：所有分类及其文章集合。

修改模板后，注意保留 Hugo 的 `{{ ... }}` 双大括号语法。模板不是普通 HTML，变量和循环必须由 Hugo 渲染。

## 5. 初级页面优化玩法

### 5.1 让首页更快读懂

- 首页标题和简介控制在一两句话，让读者迅速知道博客主题。
- 首页优先展示常读分类或近期文章，避免重复堆放整篇文章内容。
- 每篇文章设置清晰标题、摘要、分类和少量标签。
- 文章很长时使用小标题、列表和代码块，让页面容易扫描。

### 5.2 调整留白、字号和头像

在 `static/css/custom.css` 添加或修改 CSS。当前 profile 缩高规则的核心是：

```css
/* 取消主题为首页 profile 设置的近整屏最小高度 */
.main .profile {
    min-height: 0 !important;
}

/* 控制 profile 内容块之间的距离 */
.profile .profile_inner {
    gap: 0.5rem !important;
}

/* 缩小头像 */
.profile img {
    width: 80px !important;
    height: 80px !important;
}
```

CSS 选择器左侧是目标元素，花括号里是样式属性。比如 `.profile img` 表示 profile 区域中的图片，`gap` 调整 flex/grid 子元素间距。优先用明确的局部选择器，避免直接重置全站的 `img`、`h1` 或 `a`。

`!important` 可以覆盖主题中优先级较高的样式，但不宜到处使用。先在浏览器开发者工具中查看原规则，再决定是否需要它。

### 5.3 添加自定义 CSS 的加载链路

当前链路如下：

```text
layouts/partials/extend_head.html
  → <link rel="stylesheet" href="{{ "css/custom.css" | relURL }}">
  → static/css/custom.css
  → public/css/custom.css
```

`relURL` 会根据 `baseURL` 生成正确的站点路径。因为生产网址在 `/blog/` 下，渲染后的 CSS 链接应类似 `/blog/css/custom.css`。使用这个写法比手动写 `/css/custom.css` 更适合部署到子路径。

### 5.4 提升文章可读性

- 开头先交代问题、结论或读者能学到什么。
- 每个段落只讲一个重点；步骤使用有序列表，选项使用无序列表。
- 命令和代码用代码围栏，并标注语言：

  ````markdown
  ```powershell
  hugo server -D
  ```
  ````

- 图片应有意义且文件大小适中；将图片放到 `static/images/`，正文中使用：

  ```markdown
  ![页面效果截图](/blog/images/page-preview.png)
  ```

  若希望本地预览和生产站点都不受路径影响，可在 Hugo 模板中使用 `relURL`；Markdown 图片也可用站点根路径写法，但应确认该路径带有 `/blog/`。

## 6. 本地预览、构建与发布

在项目根目录打开 PowerShell：

```powershell
# 启动本地预览；草稿文章也会显示
hugo server -D --disableFastRender
```

浏览器访问：<http://localhost:1313/blog/>。保存文件后 Hugo 通常会自动刷新。CSS 没更新时，先强制刷新浏览器；如果本地服务器未重新加载，再停止并重新运行命令。

正式构建可用：

```powershell
hugo --minify
```

生成结果在 `public/`。当前 `.github/workflows/hugo-deploy.yml` 配置为 push 到 `main` 后，GitHub Actions 用 Hugo 0.168.0 构建并发布 GitHub Pages。主题是 Git submodule，工作流已配置 `submodules: recursive`。

发布前建议本地预览改动、确认链接和图片都能打开，再提交并推送：

```powershell
git status
git add content layouts static hugo.toml
git commit -m "Update blog content and layout"
git push
```

只把本次真正修改的文件加入提交。不要把临时构建目录、个人缓存或无关文件一起提交。

## 7. 常见问题排查

| 现象                     | 检查位置和处理方法                                           |
| ------------------------ | ------------------------------------------------------------ |
| CSS 修改没有生效         | 确认编辑的是 `static/css/custom.css`；查看页面源码是否加载 `/blog/css/custom.css`；强制刷新缓存。 |
| CSS 返回 404             | 检查 `layouts/partials/extend_head.html` 的 `relURL` 写法，以及文件是否位于 `static/css/custom.css`。 |
| 图片本地能看、线上不显示 | 检查文件是否在 `static/`，链接是否带站点子路径；避免把资源路径硬编码到错误的域名根目录。 |
| 新文章没出现在网站       | 检查文件是否位于 `content/posts/`、front matter 是否正确，以及 `draft` 是否为 `false`。 |
| 首页分类没有文章         | 检查文章 front matter 的 `categories`；当前首页只遍历已存在的分类。 |
| 修改主题模板后升级丢失   | 将需要的覆盖模板放在项目自己的 `layouts/`，而不是直接改 `themes/PaperMod/`。 |
| 部署后旧版本仍显示       | 查看 GitHub Actions 工作流是否成功，确认 Pages 发布完成，再清浏览器缓存。 |

## 8. 安全的初学者修改顺序

1. 先确认要改的是内容、配置、模板还是样式。
2. 只改对应位置：文章改 `content/`，配置改 `hugo.toml`，样式改 `static/css/custom.css`，页面结构改 `layouts/`。
3. 用本地服务器检查桌面和手机宽度下的显示。
4. 一次调整少量内容，出现问题时容易回退。
5. 发布前检查 `git status`，确认提交的都是预期文件。
